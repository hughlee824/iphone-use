# Standard AX observations

Standard can augment its Apple screenshot with a read-only AXP native snapshot. It uses the same host AX cache, compact rendering and `inspect` queries as Runner. Standard text input can bind the observed native editor to HID keyboard input.

## Session-owned automation enhancement

Standard connect attempts to enable richer AX exposure before preparing its observation worker. Under the existing exclusive control-device lock, a bounded subprocess of the same CLI uses MobileDevice's existing USB pairing/session APIs to write the fixed `com.apple.Accessibility` / `AutomationEnabled` key to `true`. It then posts `com.apple.accessibility.cache.automation.enabled` through the existing CoreDevice notification interface. No arbitrary preference writer, Runner, iPhone helper app or new third-party runtime is involved. USB discovery, pairing validation and lockdown session cleanup share the native transport helper.

`status.axAutomation` (also returned by connect) separates the state, write acknowledgement, notification acknowledgement and pending cleanup responsibility. `enabled` means both requests were acknowledged; it does not prove every App has exposed every element. No reliable original-value readback is claimed. This is explicit enable/disable ownership: cleanup writes `false` and posts the same notification, rather than restoring a previous value or deleting the key. The preference is device-wide; unrelated automation tools do not participate in this host's ownership lock and must not concurrently depend on it.

Enable is attempted once per new session. A failed or unknown enable result triggers one compensating disable attempt. The session still supports its existing screenshots, actions and available baseline AX; AX collection failures retain screenshot fallback. Ordinary observations and read-only transport reconnection never toggle the preference or retry enable. Borrowing an existing session does not create a second owner.

Disconnect, idle expiration, handled termination signals and startup failure use the host's common cleanup path: stop AX observation connections, attempt disable independently of the cancelled input token, then release the device lock. `cleanup.axAutomation` reports the result; unconfirmed disable makes `shutdownAcknowledged=false` and therefore disconnect unsuccessful, even when local connections have closed. Repeated teardown returns the saved cleanup facts without another write.

A private per-device journal in `~/.iphone-use/ax-automation/` records responsibility before dispatch and survives session-directory removal. It is intentionally independent of state/config overrides. On the next standard connection, pending cleanup is attempted before any enable; failed recovery prevents enable for that session. The helper inherits a duplicate of the session’s default-root device control lock through stdin, holds it until process exit, and verifies its device/file identity before any mutation. Standard, Runner and setup all use this same admission lock: even after host SIGKILL, a live helper prevents a successor from taking over. Duplication preserves the existing lock without an unlock/reopen gap; neither parent nor helper explicitly unlocks a shared descriptor. The related CoreDevice notification subprocess inherits the same lease, so killing its parent cannot let a late notification cross a session handoff. Unrelated child tools receive null stdin and do not inherit this lease. The separate mutation lock and journal token still reject overlapping or superseded operations. Busy cleanup remains pending, never successful by inference.

The parent bounds each helper to 28 seconds; the helper also terminates itself after 25 seconds if orphaned. The notification tool uses its existing five-second tool timeout and retains the lock until exit; a still-live orphan blocks new sessions with `device_busy` rather than permitting unsafe takeover. SIGKILL, host power loss, an unreachable phone or private-service failure cannot guarantee immediate device-side disable. The journal retains the obligation for a later standard connection; there is no background retry daemon. A successful write/notification is not authoritative preference readback, and removing local state cannot undo a device mutation.

## Native transport

Standard attempts AX automatically. At connect, the same CLI binary prewarms owned `_observation-worker` processes for AX and Instruments screenshots, using MobileDevice to open an owned USB CoreDeviceProxy service, the shared device-service transport backed by the built-in bounded IPv6/TCP client, system RemoteXPC for RSD/device information, and system AccessibilityPlatformTranslation/DTX for the read-only snapshot. No Python, pymobiledevice3, root access, system network interface, external helper installation or XCTest Runner is needed for this path.

The shared [device-service provider](../Sources/AppleNativeBridge/Transport/CoreDeviceProxy/DeviceServiceTransport.h) owns USB lifetime, RSD discovery, device-identity validation and advertised service endpoints. AXP consumes its byte streams and keeps its own DTX/AX protocol. Existing CoreDevice HID/media service acquisition remains unchanged. Duo keeps devicectl display selection; unsupported native screenshot orientation/topology also uses that path.

The [DeviceIP client](../Sources/DeviceIP/include/DeviceIP.h) is project-owned C code using Apple system socket and clock APIs, with no third-party network stack. It runs on one owned worker thread, once per isolated process, with at most four active outbound IPv6/TCP streams. The USB handshake fixes the MTU at 1280; transmitted TCP payloads are capped at 1200 bytes and the peer's MSS. Each flow has a 16 KiB send queue and a 65535-byte receive window, with bounded out-of-order storage. Four bounded IPv6 fragment records support reassembly; overlap rejects the datagram and resource pressure evicts an incomplete datagram for possible TCP retransmission. Rejected IDs occupy a separate 64-entry bounded quarantine, so they do not pin payload buffers; quarantine exhaustion explicitly fails the observation instead of forgetting live rejected IDs.

The client validates endpoints and TCP checksums, trims overlapping retransmissions, tracks ACK/window updates, and handles half-close, resets, cancellation and sequence wrap. RTT-based retransmission timers use conservative backoff and congestion limits; a retransmitted SYN starts data at one MSS, and an idle sender shrinks to its initial window before resuming; zero-window probes do not consume new sequence bytes. TCP retransmission repeats transport bytes, never a new AX request. There is no host IP listener, packet forwarding, system interface creation or reusable global connection pool.

This is a restricted CoreDeviceProxy client, not a general-purpose Internet stack. It does not negotiate window scaling, SACK, timestamps or ECN, and does not support urgent data, IPv4, routing or arbitrary IPv6 extension-header chains. Unsupported traffic cannot produce a partial AX success: the existing snapshot validation and helper deadline retain screenshot fallback. Short diagnostic helpers retain a 22-second flow lifetime. Session-owned observation helpers opt into explicit teardown instead; per-request deadlines still bound impaired-link recovery.

The provider does not use or close the existing remoted RSD session, change pairing, or relax the CoreDevice broker rules used by HID/media. Timed-out child processes are terminated and their owned USB streams close. A failed generation is never reused. A read-only acquisition may be restarted once after an explicitly classified connection failure within the original request deadline, including time spent retiring the old connection. The helper preserves a structured error kind through cleanup: known disconnects and reply timeouts allow rebuilding; semantic refusals, invalid data, resource limits and unknown errors do not. Error-message wording never grants a retry, and a retry never receives a fresh deadline. No input is replayed. Native runtime/private-service incompatibility fails back to screenshots.

For read-only AX and native screenshot acquisition, DTX interruption status `2` permits rebuilding only when the same transport has reported disconnect or its channel reports cancellation. These facts can arrive after the reply callback; waiting for them uses the existing request deadline. An uncorroborated interruption and other nonzero statuses remain non-retryable refusals, even if another disconnect is observed. Both acquisition paths use the shared DTX classification; it does not authorize retrying actions or replaying input.

The adapter requires the supported AXP API version, an existing USB pairing, and an eligible primary portrait display. Dormant wireless media surfaces are allowed; unsupported orientation or ambiguous display topology falls back to screenshots. Existing standard-mode toolchain/DDI requirements remain; this does not promise every App exposes all screen content.

## Connection lifecycle and receive budgets

Connect prepares optional AX and screenshot services. Requests reuse each service serially; AX and screenshot services can run concurrently. Each process owns its USB/RSD/service connections, separate from HID, preview and recording. Disconnect or session idle expiration releases only these owned connections. A helper also exits after 30 minutes without an observation request. Pending requests are bounded independently of idle time. Timeout, malformed protocol or process failure retires the old process; generation and request IDs prevent late output from becoming a new observation.

AX receive limits are 20 MiB per packet, 40 MiB of queued bytes, 128 queued packets and 40 MiB per observation. Dequeue releases queue capacity but not the current observation's budget. Existing backlog is charged to the next observation. Lifetime traffic is diagnostic only and saturates rather than wrapping; it does not terminate a healthy connection. Archive and tree validation remain in force.

A live AX result carries a parent-validated connection lease; it does not claim the connection was closed after every read. Shutdown reports subscription, connection and tunnel cleanup separately. The short `_axp-observe` diagnostic command still closes its connections per invocation.

Standard observation, input-preflight screenshots and post-action samples share the persistent screenshot path. Lock state, backlight state and all-black image content do not prevent returning a valid screenshot. No external lock-state or duplicate display CLI checks run on this path. Two lightweight geometry reads on the worker's existing DeviceInfo connection bracket the untagged Instruments PNG; display identity, scale, dimensions and orientation must agree. Input source, target validity, local pixel and deadline checks remain in place. A provider change invalidates the old action reference. Native portrait capture is enabled on eligible single-screen iPhones; Duo and unverified rotations retain devicectl.

## Observation contract

- Screenshot capture remains mandatory. AX failure, unsupported service/version, malformed or incomplete data, or timeout produces `ax=unavailable` with a reason; no automatic Runner fallback occurs.
- The native helper owns its own USB tunnel and semantic connection. It neither uses nor closes the HID/media connection. Reads are bounded and never issue AX actions. There is one outstanding semantic query; timed-out streams are closed and not reused.
- Ordinary `observe` starts the isolated AX read and one fresh Apple screenshot request concurrently, joins both, then publishes one observation ID. Device, generation, display identity and screen geometry must agree. The AX helper checks its application root and selection before and after its snapshot. If the centre has no AX hit (including hit-test error 8), the worker requests the frontmost application from the same AXP connection. Its application token must match the root. A fallback used before collection is confirmed again afterwards, and any successful final hit must agree on the process. There is no second screenshot bracketing AX and no pixel-equality requirement. Screenshot failure cancels and joins the owned AX task before returning; AX failure retains the single screenshot. Session cancellation never publishes a late result.
- `observationAcquisition` records the strategy `parallel_ax_screenshot`, `atomic=false`, the host Unix-clock request start/finish for each branch, and whether their intervals overlap. These include connection, transfer and processing work; they are not device sampling instants. A shared ID or overlapping intervals does not prove simultaneous screen state. The agent reads both AX and PNG, using AX for semantics and the screenshot for layout, overlays and content absent from AX. Reobserve when a meaningful conflict prevents selecting a target, not merely because an animation or clock changed. Invalid snapshots and identity/geometry conflicts still retain screenshot fallback.
- After standard `type` queues a paste shortcut, it reads AX and then takes one screenshot (`ax_then_screenshot`). The caller can inspect the result immediately. An inconclusive frame can be followed by a read-only observation.
- Default standard taps compare consecutive fresh PNGs for up to 1.5 seconds, using the same pixel and context checks. The first equivalent pair selects its second PNG immediately. At 1.5 seconds new screenshot requests stop. The persistent screenshot worker checks the same host-monotonic cutoff after its initial display query, immediately before requesting pixels. An expired sample leaves the connection available for the next capture. A pending request may finish within its own timeout. Its valid PNG is selected even when it arrives after the cutoff, with `stable=false`. A failed acquisition falls back to the latest valid PNG in the same context. Context invalidation or cancellation prevents reuse of an earlier frame. A single AX read follows selection (`selected_frame_then_ax`), with the selected PNG’s original capture interval and no extra screenshot. For other actions, stability sampling may collect multiple images before the concurrent observation; its readiness evidence is checked against the final screenshot. The one-image contract applies to ordinary `observe`, not to the entire action workflow.
- `sourceBundleId`/`axApplicationBundleId` identify the application selected by AX hit-testing or the validated AXP frontmost application token. They do not upgrade standard's `foreground=unverified` into a verified foreground-app identity. `axScope=application` differs from the screenshot's `scope=screen`; system overlays can be absent from the tree.
- `coverage=unknown` remains explicit even when `source_truncated=false`. Native custom drawing may have no AX text. `visible` does not prove pixel visibility or hittability; enabled/focus values not returned by the source remain unknown.
- The whole returned tree is cached. Compact output and query pagination do not discard source nodes. Same-label occurrences remain distinct; invalid geometry is unavailable rather than a zero-coordinate target. Raw source attributes are available through `inspect`.
- Standard supports `inspect oN:eN` and `type oN:eN` on a uniquely identified native editor. A focus tap requires a fresh AX hit on the editor at its observed position. All touch and keyboard input uses HID. General element tap/focus/clear/press remain Runner operations.
- AX is collected once for the final observation. Semantic typing also reads AX to validate the target before input. Tap readiness describes the selected screenshot pair. Other default actions revalidate their earlier readiness against their final concurrent screenshot.

The agent receives the screenshot and compact AX together. It uses AX for text/state/structure and the image for layout, occlusion and content not exposed through accessibility. There is no built-in OCR or inferred replacement tree. Failure to match a cached node does not prove the target is absent from the screen.

Standard compact AX shows a `tab_bar` when a confirmed visible button with the native button trait belongs to a native `UITabBar` or to a structural container with the native tab-bar trait. The button can be a direct child or descend through unnamed layout wrappers with no AX hint or other observed control semantics. Its original reference becomes a display `tab`, with `selected=true` when the button carries the selected trait. A tab-bar trait on an action button alone does not establish a bar. Toolbar actions and text in custom navigation retain their captured roles. These display labels use the cached hierarchy and require no device query.

## Full structure, candidate visibility and keyboard presentation

The read-only collector first exports the full structural snapshot without requesting per-node `visible`. It then enumerates native semantic candidates, records their reported visibility and preserves candidates absent from the structural traversal as separate supplemental nodes. Supplemental nodes have no invented parent, explicitly unknown hierarchy and an untraversed reported child count. A successful candidate visibility read with no value is recorded as unknown. The node remains inspectable, is counted in `axCollection.unknownVisibilityCandidateCount`, and supplies no verified visibility or input authority. The combined result remains bounded; malformed replies, correlation errors and timeouts retain screenshot fallback.

When the current full structure identifies exactly one native keyboard layout root, one keyboard-subtree snapshot reads native visibility for its keys. Candidate identities found in that snapshot reuse those values; unmatched candidates use individual reads. Ambiguous keyboard layout roots use the individual path. Values are not inferred from geometry, reused across observations or defaulted to true. Noncandidate nodes without a reported visibility value remain unknown. Existing root/display checks, helper deadlines, screenshot association and input semantics are unchanged.

When the structural tree has no keyboard layout root, there are at least 16 candidates and an individual supplement identifies a native keyboard key, standard makes one shallow application query. A unique same-process keyboard window permits one subtree read. A candidate can reuse its attributes only when the window contains its exact identity once and reports a native Boolean visibility. Other candidates continue through the individual path. If the shallow query finds no unique window, standard stops starting new out-of-tree supplement requests after 150 ms. An in-flight query can finish later. Existing structural candidates still receive their visibility checks. The compact output reports the number of missing supplements and the cached snapshot marks the source as partial. This budget applies only to that fallback branch.

The common observation cache retains all structural nodes, native attributes and identities, including ordinary keyboard keys, plus the supplemental nodes. For this collection strategy, the common presentation selects queried semantic candidates plus native keyboard layout context, then applies its existing viewport rules. Named independent leaf controls directly inside an original visible candidate may also be presented when their native identity is distinct and their frame lies within the parent, screen and known clipping bounds. This local supplement does not query the device or infer visibility, enabled state, focus or action eligibility. It does not expand through newly added nodes or unknown/hidden parents. Other unqueried structural nodes remain cached with unknown visibility; omission from this projection does not mean they are invisible. Default presentation also omits recognized character-key leaves inside the native keyboard: a single printable ASCII character, or an explicitly identified space key. Unknown keys, functional controls, input fields and supplemental nodes remain eligible for the existing viewport presentation. Keyboard layout context remains available; a keyboard's presence does not establish input focus. Runner nodes without this native keyboard evidence keep their current presentation.

Ordinary keyboard character keys are folded in compact output. Use `inspect` or cached queries to read them and their original native visibility. The snapshot records semantic-candidate visibility coverage and unknown supplemental hierarchy. Raw remote identities remain inspection evidence only and never become Runner action identities. AX is still a non-atomic, application-scoped observation; custom drawing and system overlays may require the screenshot.

## Acquisition timing and retained evidence

Ordinary observations retain one PNG, the complete AX snapshot and `observationAcquisition` timing metadata. They do not produce `axScreenComparison`, `ax-before.png` or a claim that the two sources show identical pixels. `--evidence-dir` archives the paired result and its request intervals for explicit retention. Archives can contain private screen content and should remain under `.local/`.

The cache and evidence exporter still support earlier diagnostic captures containing `axComparisonScreenshot`; such historical images follow normal eviction and cleanup and never become fresh action references. Post-action readiness comparison remains separate from AX association. Device/display and application-root/process checks remain enforced; coordinate input retains its independent [action guard](screen-guard.md).

## Display validation diagnostics

Display validation retains its existing eligibility rules and does not retry automatically. Rejections identify the display-array index and the first failing field, such as `displays[1].backlightState`; an unsupported or uncertain display still falls back to the screenshot.

For a local diagnostic capture, run the same built helper with `IPHONE_USE_AX_DISPLAY_DIAGNOSTICS=1` and redirect stderr to a file under `.local/`. Each completed display validation emits one `AX_DISPLAY_DIAGNOSTIC` JSON line with its before-hit/after-snapshot phase, sample number, Unix start time, monotonic elapsed duration, and bounded field summaries. Missing, null and unexpected types remain distinguishable. At most eight initial display entries plus an offending entry are included; omitted entries are counted. Names, unique IDs, arbitrary device strings and AX content are excluded. Stdout remains the ordinary AX result, and the parent observation helper continues to discard stderr. Default captures do not emit these diagnostic lines.

A later valid display sample alone does not prove the rejected sample was safe. Investigate the recorded field and timing before changing eligibility or adding bounded resampling; never reuse an earlier target/display identity or replay a semantic request to hide a failure.

## Native stage timing diagnostics

For an isolated timing capture, set `IPHONE_USE_NATIVE_TIMINGS=1` when running the built `_axp-observe --device <device-id>` helper, redirecting stdout and stderr to separate files under `.local/`. Stdout retains the ordinary AX result. Stderr emits bounded `NATIVE_STAGE_TIMING` JSON lines containing only a fixed stage name, version, monotonic start/end times and elapsed milliseconds. Default observations emit no timing records; the parent helper continues to discard stderr.

Stages cover MobileDevice discovery/session/service startup, tunnel negotiation, RSD validation, service connections, DTX/API/subscription setup, display queries, hit/root/tree requests, export and cleanup. Request records distinguish encoding, acknowledgement, subsequent response waiting, decoding and validation. A response can already be queued during acknowledgement, so later wait time alone is not device processing time. Repeated request kinds appear in execution order. Records represent completed stages; a missing record after failure is not a zero-duration stage.

Parent scopes overlap their children: for example, `observation.transport_open` includes `transport.tunnel_open`, which includes `tunnel.usb_service`. Do not sum across scopes. `observation.total` includes connection setup and cleanup but excludes helper process launch and final JSON serialization/output. Logging overhead is included in parent scopes and excluded from the following sibling stage. Keep cold-connection totals separate from request latency on an existing connection. These diagnostics do not change request ordering, deadlines, eligibility, retries, screenshot association or action semantics.

## Post-action frame diagnostics

For local transition analysis, set `IPHONE_USE_POST_ACTION_DIAGNOSTICS_DIR` to an absolute path under `.local/` when connecting a standard session. The host inherits this opt-in setting. Each post-action observation buffers each acquired PNG once, then exports them to a private UUID directory with `manifest.json` after acquisition finishes. It does not request additional frames or change input guards, sampling intervals, stability thresholds, deadlines or action outcomes. Ordinary `observe` does not create this trace.

The manifest retains per-frame metadata, host monotonic acquisition intervals and the original stability result and the final screenshot and AX request intervals. `captureIntervalsUptime` identifies individual screenshot/check intervals; these are host request intervals, not device exposure timestamps or input acknowledgements. Correlate them with the action receipt's host input timestamps where available; App launch has no HID completion timestamp. `postActionDiagnostics` reports export success, export duration and omitted-frame counts. Export failure does not turn an already executed action into a failed/retryable action. Capture failures retain the already buffered evidence when export is possible.

Retention is bounded to 32 PNGs / 64 MiB and 128 sample records per observation; omitted frames are counted. No PNGs are written between samples. Export time adds to diagnostic command latency, and enabling retention still has some memory/bookkeeping overhead. These private files are outside normal observation-cache eviction and require explicit local removal. Leave the variable unset for normal operation.

`nativeScreenshotDiagnostics` separates the persistent worker round trip, base64 decode and host metadata validation. Worker timings cover `takeScreenshot`, the preceding and subsequent display geometry queries and base64 encoding, with host monotonic request start/end timestamps. `takeScreenshotMs` includes service and transport latency, not just device rendering. The round-trip residual after `beforePublishMs` includes IPC, serialization, scheduling and any connection recovery; it is not pure USB time. Local PNG validation remains in `captureTimingsMs.appleImageValidation`. Nested timings must not be summed twice.

`axCollection.stageTimingsMs` records completed display, hit, root and tree stages; `collectionTimingsMs` breaks the tree stage into structure, candidates, keyboard and candidate visibility. These bounded numeric diagnostics do not alter AX queries or coverage. Tree totals include their collection children and must not be added to them. Missing timings are unknown, not zero, and host intervals include transport and decoding rather than only device processing.

For the full application tree only, `stageTimingsMs` reports three host-side parts of `ax.structure_read`: `ax.structure_ack` is the DTX send through acknowledgement, `ax.structure_wait` is the subsequent time waiting for semantic reply packets at the host queue, and `ax.structure_unpack` is archive bounds checking plus secure unarchiving on the host. Wait and unpack accumulate across intervening notifications. These are elapsed intervals, not device CPU or packet-transit measurements; small encoding and correlation costs remain in the parent. Supplemental and keyboard snapshot requests do not contribute to these three fields.


## Compact list presentation

The unnumbered `[app]` root groups the captured nodes under their AX source bundle ID and screen-point bounds when known. The observation ID and status flags stay in the header.

Standard retains the original node references when presenting supported native list cells as rows. A list with a confirmed visible candidate can expose readable text in its UIKit or collection-view list rows. A text leaf can be recognized by its native static-text trait. A confirmed unnamed button can also expose its direct text label within the button’s bounds. The header explains the `?` suffix (unknown AX visibility) only when a displayed node carries it. Use the original element number for inspection. A named image with unknown visibility needs a nonempty intersection through every enclosing frame up to the row. Images with incomplete geometry remain available through `inspect`. The row and scroll bounds constrain displayed geometry. A confirmed full-width edge bar clips overlapping lists in its own content container. When confirmed row content also lies beyond the bar, the compact tree retains both exposed bands, separated by a vertical bar in `clip=`. A hidden image leaf without a label or value contributes no text to a visible button’s name, even if the image lacks a frame. If an owning row lacks bounds, only independently confirmed, located descendants may supply content. Field deduplication accounts for the owning control and the exposed portion of each frame. Complete rows retain their own label text after subtracting exact, unambiguous child text at comma-delimited field boundaries. A confirmed named control inside the same row may already express its child labels as an ordered whole, or supply a matching label and value. The compact form omits those repeated text nodes and preserves partial matches and distinct values. Child text may contain commas. Ambiguous matches retain the original label, including any localized status text. Clipped rows and their partially exposed composite controls omit aggregate labels and values. Individually located children supply the readable content. A full-width custom top bar alongside UIKit navigation content can establish the upper viewport edge when it contains a labeled AX header and a confirmed visible button. This projection changes neither the captured tree nor the evidence required for coordinate input. App-drawn overlays and unrecognized containers can limit geometric clipping.

## Verification

Device-free tests cover archive graph/byte limits, incomplete trees, unknown fields, duplicate labels, display/context mismatch, failure fallback, shared cache queries, standard element-action rejection, native stream backpressure, large responses, packet loss, half-close/reset/cancellation and subprocess isolation. Physical acceptance is separate; use the exact built CLI and verify the screenshot and AX from the same observation. Do not treat historical research captures as acceptance of a new build.
